Verdikt.

AI reads the case. Deterministic code writes the reply. Humans decide.

The problem

A patient-assistance application is a stack of four documents: enrollment form, income proof, insurance card and prescription. The eligibility decision is small, but intake, eligibility, fulfillment and compliance each re-read the same stack. That re-reading is where the days go. Verdikt reads the stack once, decides against the program's own rules, and sends a reply that no language model touched.

How it works — five stages

Ingest
MiniCPM-V 4.5

Reads attachments into the program's field schema.

Triage
Nemotron Nano

Classifies the case and routes it. Rule-based fallback.

Decide
Qwen3-Embedding + Nemotron Super

Retrieves rules, then a cited verdict.

Deliver
No model

Merges the verdict into a frozen, human-approved template.

Remember
No model

Audit entry per stage; template hash; render fingerprint.

Architecture — one line that matters

In

Email (IMAP), JSON API, MCP tools. Fax and scans arrive as email attachments.

→
AI-in · reviewable

Read, classify, retrieve, reason to a structured verdict with citations.

→
Deterministic-out

Frozen template merge. No model on this path. Reply letter plus JSON verdict.

FastAPI web, background worker, Postgres, Redis and S3-compatible storage. All model calls go through one Nebius Token Factory endpoint; the model for each stage is configurable per program. A boundary test fails the build if the render core imports the AI layer.
